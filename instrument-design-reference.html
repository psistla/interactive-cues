Precision you can read at a glance. Calm you can work in all day.

A design reference for an application that is read in and operated in equally. Type does the talking; everything else stays out of the way.

01

Point of view

Five commitments. Each one closes an argument that would otherwise reopen on every screen.

Type is the interface

Hierarchy comes from size, weight, and tracking. No eyebrows, no decorative labels, no icons standing in for words. A screen with the colour removed still reads correctly.

Structure is drawn, not implied

Hairlines and one-pixel rings define regions. Shadow is reserved for things that float: menus, palettes, toasts. Nothing on the page plane casts one.

One hue works; amber points

Indigo is every action, link, focus, and selection. Amber appears only when the system needs the eye now: the production indicator, a pinned item. If amber is decorating, it is wrong.

Data sits in mono

Identifiers, timestamps, counts, and durations are set in the monospace face with tabular figures. Columns align without effort and numbers stop jittering when they update.

Density is the user's choice

Comfortable and compact are first-class modes, persisted per user. The header toggle switches this document; the application does the same.

Accessibility is enforced, not reviewed

Contrast is checked at the token layer, focus and keyboard at the component layer, motion at the root. A screen inherits compliance by construction.

Rule: any number a user might compare against another number is mono and tabular. A number inside a sentence stays in the sans. Metric values use the mono face at display sizes so the tile reads as an instrument, not a headline.

Measure and rhythm

  • Prose measure 60 to 68 characters (640px at 15px). Docs measure 68 to 72 at 17px.
  • Headings never sit alone: a heading is always followed by content within 12px, and preceded by at least 32px.
  • Two consecutive type sizes never differ by less than 2px; if they do, one of them is a weight change, not a size change.
  • Truncate with an ellipsis only on identifiers; wrap everything a human wrote.

Elevation

ring: page plane
lift 1: controls
lift 2: menus
lift 3: modals, palette

A ring is a 1px box-shadow, not a border, so it never changes layout and stacks cleanly with lift. Panels on the page plane have a ring and no lift. Dark mode raises lift opacity and keeps the ring.

Motion

120ms for hover and toggles, 180ms for standard transitions, 220ms ease-out for entering, 140ms ease-in for exiting. Motion answers a user action and shows what changed. There are no page-load sequences, no scroll reveals, no ambient loops; the skeleton shimmer is the single exception and it stops under reduced motion.

06

States

Loading, empty, error, and success are the screens most users meet first. A component is not finished until all four exist and read consistently.

Loading

Skeleton in the shape of the content. Under 300ms show nothing at all; a flash of skeleton is worse than a short wait.

Empty

No pipelines yet

Create one from a template or import a definition.

Success

Confirm with the verb the button used. Toast, five seconds, dismissible, with undo where the action is reversible.

Optimistic by default: the row updates before the server confirms, and reverts with an error toast if it does not.

10

Features a technical audience expects

Absent, any of these reads as immaturity. Present, none of them will be mentioned.

  • SSO and roles on day oneEntra ID or OIDC; roles visible on the member list.
  • Audit logWho, what, when, from where. Filterable, exportable, linked from every record.
  • Undo over confirmReversible actions undo from the toast; only irreversible ones confirm, by typed name.
  • Environment switch with an unmistakable prod stateThe one place amber is always on.
  • Public status page and dated changelog
  • Command palette and a shortcut sheetEvery shortcut is shown next to its action, so the UI teaches the keyboard.
  • Deep linksFilters, tabs, selection, and range live in the URL.
  • API and CLI parity, export everywhereAnything the UI does, the API does; every table exports CSV and JSON; every id copies.
  • Density and theme, persisted per user
  • Agent-ready surfaceStable accessible names and data attributes, an OpenAPI spec, and a tool manifest so AI agents operate the product without scraping it.
